# 畫面改版定案（2026-11-06）

這份是畫面改版的最終定案，實作時照這份和 `final-*.html` 的設計稿做。原本的分支已經刪除，這份規格和 `layers/` 現在放在設計稿 artifact 裡。開始實作時，把它們連同設計稿放回 repo 的 `docs/superpowers/2026-11-06-redesign/`；做完、結論併進 `docs/design.md` 和 `DESIGN.md` 之後，整個資料夾刪掉（CLAUDE.md「改設計」）。

行為改動只有兩項：**拿掉狀態列**（第 1 節）和**桌子與家具的固定格線**（第 8 節）。其他全部只改畫面長相：物件尺寸、座位分配（`src/state`）、狀態規則、動畫、資訊卡內容都不變。

線上的設計稿（同樣六個情境，可以切日夜）：https://claude.ai/artifact/YZuayVAdgnoVujXh9Tq5yf

## 怎麼看設計稿

`final-*.html` 是六個情境的定稿，各自是一個獨立的 html，用瀏覽器直接打開，網址加 `?time=day` 或 `?time=night` 切日夜：

| 檔案 | 情境 |
| --- | --- |
| `final-one.html` | 3 層樓、5 位員工、2 位助理；2F 一人等你處理，1F、3F 各一人輪到你 |
| `final-multi.html` | 5 人裡 4 人等你處理，其中兩人在同一層 |
| `final-empty.html` | 2F 的 Explore 助理做完退場，留下空桌和空椅子 |
| `final-offline.html` | 連線中斷 |
| `final-card.html` | 打開 2F 等你處理那個人的資訊卡 |
| `final-wide.html` | 和 `final-one` 同一批人，視窗 1920×1080；要用這個尺寸看 |

設計稿是用 `main` 上的前端真的跑出畫面拍下來，再依序疊上 `layers/` 的圖層（`01` 到 `15`）做成的。**精確的座標、尺寸和色票以 `layers/` 的原始碼為準**，這份文件只寫做什麼、改哪裡、要守什麼。圖層照編號順序疊，後面的覆蓋前面的。

## 5. 名牌、樓層招牌、電梯面板

- **名牌圓章**（`08`）：「!」「✓」前綴改成 12px 圓章，等你處理是白底紅字加墨線圈，輪到你是 `#4a3000` 底、琥珀字；後面的文字和名牌底色不變。`view.ts` 的 `platePrefix`／`floors.ts` 的 `plateText` 要把前綴和文字分開給 `floor.ts`。
- **名牌兩行**（`09`）：字級不變（13px 粗體、行高 15），最寬 112，最多兩行，往下長，落在桌子的正面擋板上。文字一律包一層內層元素，**截行放在內層**，否則被截掉的第三行會從外層的 padding 露出來（`card.ts` 的 `activity()` 同理）。英文在連字號或字與字之間斷行（`word-break: normal; overflow-wrap: anywhere`），不要用 `break-all`。有圓章時靠左，沒有時置中。
- **樓層招牌**（`01`、`08`）：樓號放在白色小牌上，數字 16px、「F」10.5px，後面接資料夾名；兩端各一顆鉚釘、下緣一階硬影（`02`）。最寬照舊是 `SIGN_MAX_W`，放不下用「…」。
- **電梯面板**（`02`、`08`）：不鏽鋼底（右側硬影），頂端一塊深藍的上下箭頭顯示窗，上下各兩顆螺絲，按鈕外圈一道金屬框和刻線。框住目前樓層的虛線框改成凹下去的軌道（淡墨色底、內側硬影、細框）。燈色、「!」「✓」、點了捲到那層都照舊。

## 8. 桌子與家具的固定格線（`15`）

原本座位從左邊依序排、家具區固定在最右端，因為桌子會往右長。結果家具永遠離人很遠，也沒有人用，1920 寬時中間還留下一段空走廊。改成先排好固定的格子，桌子和家具混排，桌子不會再把家具推走。

**格線**：只跟樓層寬有關，各層同寬所以各層相同。從左邊開始，三張桌子接一個家具區，餘數平均給家具區。

```
U     = width − 2 × sideGap
bays  = max(1, floor(U / 540))        // 540 = 3 張桌（120）+ 最窄的家具區（180）
desks = floor((U − bays × 180) / 120)
bayW  = (U − desks × 120) / bays
```

| 視窗寬 | 樓層寬 | 排法（D 桌、B 家具區） |
| --- | --- | --- |
| 900 | 828 | 3D B 2D，家具區寬 180 |
| 1920 | 1848 | 3D B 3D B 3D B 1D，家具區寬 200 |

**規則**

- **座位對格子**：第 i 號座位對到第 i 張桌子的格子。`src/state` 的 `freeSeat` 不動，人照舊坐號碼最小的空位。
- **格子都有桌有椅**：沒人的格子畫空桌，椅子加 `.vacant`（`filter: saturate(.3) brightness(1.1)`），否則一整排亮藍椅子比坐著的人還搶眼；有人就變回原本的藍。天花板燈條跟著每個格子，空桌也有。
- **窗和掛畫只開在桌子區的牆上**，家具區的牆留給高的家具。第一組的左邊是招牌，所以只在第三張桌子上方開一扇窗；不足三張時不開（招牌會被壓到，這個情況沒有畫過）。其他組：三張是窗、掛畫、窗，兩張是掛畫、窗，一張是窗。掛畫三幅輪流，起點依樓層。
- **家具組**：第一個家具區照舊用 `furnitureSet(key)`，同一層永遠同一組；後面的家具區依 `SETS` 順序往下輪。每組在家具區裡置中、間隔 12；地毯跟著有沙發的那組。
- **超過人數不另外設計**：格子不夠時照舊整棟加寬、整頁橫向捲動，右邊繼續往下排。
- **視窗改變寬度**：格線重算，桌子、人和家具直接換到新位置，沒有動畫。

**已知限制**：拿掉狀態列後，樓層被撐得比視窗寬時，等你的人可能在視窗右邊外面，電梯按鈕只上下捲，點了也看不到。這輪決定不處理。

**要改的檔案**

- `web/src/floors.ts`：新增純函式 `seatGrid(width)`，回傳每個座位的中心 x 和每個家具區的 `{ x, w }`；`seatCenter` 改查格線。`buildingWidth` 改成放得下桌數最多那層的最小寬度：`desks × 120 + ceil(desks / 3) × 180 + 48`。`GEO.furnitureW` 拿掉，換成最窄的家具區 180。
- `web/src/building.ts`：`placePeople` 用格線放人。
- `web/src/floor.ts`：桌數 = `max(格子數, f.desks)`；空桌的椅子加 `.vacant`；`this.furniture` 從一個變成每個家具區一個，用 `left`、`width` 定位；`furnKey` 的判斷要加上格線，寬度變了才會重排。
- `web/src/furniture.ts`：`furnitureSet` 多收家具區的序號；`layoutSet` 收家具區寬；`windowXs(width)` 改成依格線算窗和掛畫的位置。`SIGN_MAX_W` 維持原值。
- `web/src/styles/building.css`：`.furniture` 拿掉 `right` 和固定寬度，加 `.chairs > .obj.vacant`。
- `test/`：`seatGrid` 的 900、1920 兩種排法，以及任何桌數下 `buildingWidth` 算出的寬度都放得下這些桌子。現有測試沒有用到這些函式，要新寫。

**文件**

- `README.md`：每層一開始就排滿桌子，沒人的是空桌；家具夾在桌子中間，不在右端。「沒有空桌就加一張」改成格子不夠時整棟加寬。
- `docs/design.md`：寫固定格線的理由；「已否決的做法」補兩條：家具區固定在右端（家具離人遠、沒人用），以及輪到你的人去用家具（位置不再固定、要多做坐姿和站姿、家具有容量上限、站姿會擋到旁邊的家具）。
- `DESIGN.md`：「右端家具區寬 200px」改成格線；家具區離右緣 24 的說明一起改。
- 程式註解：`floor.ts`、`furniture.ts`、`objects.ts`、`building.css` 裡的「右端」。
