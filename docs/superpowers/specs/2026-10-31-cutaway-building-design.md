## 意圖

等角房間在畫面上是斜的平行四邊形，放進長方形畫布只能填滿一半左右，四個角落是沒有東西的暗角。使用者覺得這些空間浪費，目的是讓畫面**更滿、更好看**，並且明確表示 2.5D 也可以推翻，所有東西都可以重新設計。

新的畫面是一棟**從正面剖開的大樓**：一個專案一層樓，人坐在桌後面向觀看者。每層都是長方形，疊起來就是畫面的形狀，所以沒有暗角。

核心需求不變（見 `2026-10-21-flat-vector-project-islands-design.md` §1，已刪除，見 git 歷史）：打開畫面最想一眼知道「有哪些專案」與「哪些 session 在等我」。

## 目標

- 整個前端畫面改成剖面大樓，**取代**等角辦公室，不保留切換。
- 頁面用瀏覽器原生捲動；每層樓放不下時，只有那層自己左右捲。
- 不管捲到哪裡，都看得到每一層有沒有人在等你（電梯面板）；同一層裡看不到的座位有人在等，也看得到提示（樓層邊緣提示）。
- 拿掉 Phaser，畫面全部用 DOM 組成；人物與家具繼續用 `clay.ts` 的黏土畫法烘成圖片。
- subagent（助理）也是員工，坐在主人那層的桌子。

## 非目標

- 不改伺服器、hook、安裝程式、狀態 reducer（`src/` 全部不動），也不改 SSE 同步（`web/src/sync.ts`）。
- 不做縮放。剛做好的自由控制鏡頭（commit `6098f00`：滾輪縮放、拖曳平移、「回到自動對焦」）隨 Phaser 一起拿掉。
- 不做自動捲到有人在等的樓層。
- 不做樓層施工、拆除的動畫。

## 反目標（做到了也算失敗）

- 畫面上出現沒有東西的大片空白或暗角（大樓比視窗矮時，上方必須是夜空，不是空白）。
- 有人在等你，但不管捲到哪裡都看不出來。
- 名牌文字糊掉，或名牌疊在別人的臉上。
- 為了這次改動修改 `src/` 底下的程式。

**刻意推翻的舊反目標**：等角設計的反目標「畫面只顯示辦公室的一部分、要捲動才看得到其他島」不再成立。使用者選擇固定層高、往下捲；看不到的樓層由電梯面板補足。

## 畫面結構

由上而下：

1. **狀態列**：沿用現在的圖例與比例條（`view.ts` 的 `summary`），`position: sticky` 黏在頁面頂端。
2. **夜空與屋頂**：星空、遠方城市剪影，大樓最高層上面有屋頂。
3. **樓層**：最高樓在上，1F 在最下面。
4. **地面**：人行道，1F 站在上面。

尺寸（CSS px）：

| 項目 | 值 |
|---|---|
| 層高（含 8px 樓板） | 200 |
| 電梯區寬 | 80 |
| 座位寬 | 120 |
| 右端家具區寬 | 200 |
| 地面高 | 72 |
| 電梯面板寬（固定在視窗左側） | 40 |

- 大樓區塊左邊留 56px 給電梯面板，樓層寬 = `max(可用寬度, 80 + 座位數 × 120 + 200)`；可用寬度 = 視窗寬 − 56 − 右邊距 16。
- **大樓比視窗矮**：大樓區塊的最小高度是「視窗高 − 狀態列高」，內容靠底對齊，上方空間就是夜空。
- **大樓比視窗高**：整頁用原生捲軸。打開頁面時捲到最底（看到 1F 與地面）。在上方加蓋新樓層時，畫面停在原本看的樓層不跳動（用 CSS `overflow-anchor`，瀏覽器不支援時，加蓋後補捲新樓層的高度）。
- **沒有人上班**：只有地面和一層空的大廳，大廳中間寫「目前沒有人上班」與「開一個 Claude Code session 就會出現」。

### 樓層分配

- 一個專案一層，專案以 `roomKey`（完整路徑 cwd）區分，招牌名稱沿用現在的規則（`folder`，同名不同路徑時顯示最後兩層）。
- 樓層順序依專案裡最早的 `arrivedAt`，從 1F 往上排。
- 專案的人全部離開後（包含走進電梯的動畫結束），那層拆掉，上面的樓層往下遞補，樓號跟著改。

### 電梯面板

- `position: fixed` 在視窗左側、垂直置中；樓層太多放不下時，面板自己可以上下捲。
- 每層一顆圓形按鈕，寫樓號，最高樓在上。
- 燈色是那層的 `floorAlert`：紅（`#d63434`）＝有真員工等你處理；琥珀（`#f2b83d`）＝沒有等你處理、但有真員工輪到你；都沒有就是暗的。
- 目前在視窗內看得到（任何部分）的樓層，用一個半透明框框起來（`IntersectionObserver`）。
- 點按鈕：平滑捲到那層（`scrollIntoView({ block: 'center', behavior: 'smooth' })`）。
- 滑過按鈕：顯示專案名稱（`title` 屬性即可）。

## 樓層內部

從左到右：

1. **電梯**：電梯門，門上的小螢幕顯示樓號。員工從這裡進出。
2. **招牌**：寫在後牆左上，「3F shop」，專案色底（不透明度 0.9）、白色粗體字，沿用現在地上招牌的配色。最大寬度 = 電梯區右側到後牆第一扇窗之前，放不下用 CSS `text-overflow: ellipsis` 截斷（取代 `signFit` 的縮字）。招牌不再放人數徽章。
3. **座位列**：一排，座位寬固定 120。
4. **右端家具**：一組正面家具。

後牆有夜景窗，窗戶間隔固定，位置只跟樓層寬度有關。

### 座位

- 桌數 = 這層最大座位編號 + 1（包含助理的座位）；座位編號沿用伺服器給員工的 `seat`。
- 沒人坐的座位是一張空桌，螢幕是暗的。
- 人坐在桌子後面向觀看者；螢幕在桌面右側，不擋臉。
- 人物素材是 `flat.ts` 的 `character()`（40×56），以 1.5 倍顯示，椅背畫在人物素材裡（`chair: true`）。

### 名牌

- 放在桌子正面，HTML 文字，13px，最大寬度 = 座位寬 − 8，放不下用 CSS `text-overflow: ellipsis` 截斷。
- 真員工：文字是 `nameplate(e)`（任務標題）；卡片色沿用現在的 `PLATE_COLORS`：工作中米白、等你處理紅色加「! 」、輪到你琥珀色加「✓ 」。
- 助理：見「助理」。
- 拿掉 `plateFit`、`plateWidths`、`plateMaxW`：寬度固定、交給 CSS，不再需要量字與分配寬度。

### 一層放不下時

- 樓層內容比可用寬度寬時，這層 `overflow-x: auto`，只捲這一層（觸控板左右滑、Shift＋滾輪、拖曳捲軸）。
- 左右邊緣各有 22px 的暗影，暗示那一側還有內容；已經捲到底的那一側沒有暗影。
- **邊緣提示**：座位中心點在可見範圍外的，算「看不到」。左、右兩側各自計算看不到的真員工：
  - 有等你處理的：那一側出現紅色圓角提示「! N ›」（左側是「‹ ! N」），N 是人數。
  - 沒有等你處理、但有輪到你的：琥珀色「✓ N ›」。
  - 點提示：在那一側看不到、而且狀態跟提示顏色相同的員工裡，挑離可見範圍最近的一位，把這層捲到讓他的座位置中。
- 捲動或視窗大小改變時重新計算。

### 家具

- 每層右端放一組正面家具，從固定的幾組裡依專案 `roomKey` 的雜湊挑一組，讓每層長得不一樣、而且同一個專案每次都一樣。
- 至少三組，例如：飲水機＋販賣機＋盆栽、書櫃＋影印機、沙發＋立燈＋邊桌。
- 全部是新畫的正面版本，用同一套黏土畫法（`clay.ts`）。

## 人物動態與狀態

### 上班

- 新 session 的專案還沒有樓層時，先加蓋一層（直接出現）。
- 電梯門打開（300ms），員工走出來，沿著樓層水平走到座位，坐下。
- 走路：`walk0`、`walk1` 每 140ms 交替，用 CSS `transition` 水平移動，速度 120px/s（座位越遠走越久）。
- 走路途中又有新事件（換座位、要離開）時，從目前位置轉向新的目的地。

### 下班

- 站起來，走回電梯，電梯門打開、進門、關上。
- 這層最後一個人進電梯後，這層才拆掉。

### 狀態姿勢

沿用 `flat.ts` 的姿勢與現在的狀態規則：

- 工作中：`sit0`、`sit1` 每 200ms 交替（打字）。
- 等你處理：`up`（站起來舉手）。
- 輪到你：`idle`（閉眼休息），頭上有打勾的琥珀泡泡（沿用現在的 `drawBubble` 外觀，改成 DOM 或小畫布）。

### 資訊卡

- 員工資訊卡的內容與「請他下班」完全沿用現在的 `InfoCard`。
- 滑到人身上出現，位置依那個人元素的 `getBoundingClientRect` 計算（卡片在人的右上方，貼齊視窗邊界）。
- 頁面捲動或任何樓層左右捲時，卡片先藏起來。

### 重新連線

- `reset` 時整棟重建，每個人直接出現在座位上，不播電梯與走路動畫。之後陸續進來的人才走路進場。

## 助理（subagent）

每位助理是主人那層樓的一位員工，資料全部來自 `Employee.assistants`，伺服器不用改。

- **外觀**：用「主人 sessionId / 助理 id」雜湊決定（沿用 `appearance` 的做法）。
- **座位**：坐在主人右邊第一張空桌；沒有空桌就接在這層最後面。助理在的期間座位不變。伺服器配給真員工的座位撞到助理時，助理換到新的座位（同樣規則重新找）。
- **名牌**：偏藍底（`#cfe0f7`，字 `#1f3550`），「↳ 描述」；有 `kind` 時是「↳ kind · 描述」；沒有描述時是「↳ 助理」。完成後是「↳ ✓ 完成」。
- **動作**：
  - 開始：從電梯走出來，走到座位打字。
  - 完成（`status: 'done'`）：換成 `idle` 姿勢，3 秒後走回電梯離開。
  - 工作中卻從清單消失：立刻走回電梯。
  - 主人下班：主人的助理一起走回電梯。
- **不算在等你**：不舉手、沒有打勾泡泡；電梯燈、邊緣提示、狀態列、分頁標題、「共 N 位」都只算真員工。
- **資訊卡**：助理有自己的卡片：類型、描述、主人的任務標題、狀態（工作中／完成）、開始時間。沒有「請他下班」。主人的卡片照樣列出他的助理（`assistantList`）。
- **空桌**：助理離開後空桌保留，直到整層沒人；避免助理來來去去時樓層寬度一直變。

  - 樓層依最早到班時間從 1F 往上排；中間一層的人走光後，上面往下遞補、樓號改變。

### 模擬劇本

`npm run simulate` 的預設劇本擴充成一次涵蓋：

- 6 個專案（超過一個畫面，要上下捲）。
- 其中一個專案 9 個 session（那層要左右捲），而且其中一位在畫面外時變成等你處理。
- 同時派出多個 subagent，有前景也有完成的。
- 有人等你處理、有人輪到你、有人下班（某層的人全部離開）。

### 瀏覽器檢查清單

實作每個階段完成時，用隔離的伺服器（HOME 指到暫存資料夾、另一個 port）跑模擬，逐項確認：

1. 3 層以下時，大樓站在視窗底部，上方是夜空，沒有空白。
2. 6 層時，打開頁面停在最底；電梯燈色正確；框住的樓層跟捲動位置一致；點按鈕會捲到那層。
3. 9 人那層可以左右捲；畫面外有人等你處理時，邊緣出現紅色提示，點了會捲過去。
4. 人從電梯走出來坐下；下班走回電梯；最後一人離開後樓層拆掉，上面往下遞補。
5. 捲在中間時，最上方加蓋新樓層，畫面不跳動。
6. subagent 從電梯出來、坐在主人旁邊打字，完成 3 秒後離開；它不會讓電梯燈或狀態列變色。
7. 員工與助理的資訊卡內容正確；員工卡片的「請他下班」有效。

## 已否決的做法

- **正面 3/4 俯視（一間長方形大房間）**：同樣沒有暗角，也保留分島；使用者選了剖面大樓。
- **等角＋外部景色**：暗角改畫風景，改動最小，但房間在畫面上的大小不變。
- **把暗角拿來放資訊或小地圖、鏡頭沿斜邊裁切、換房間形狀**：都只能減少暗角，消除不了。
- **專案多時樓層變矮，或改成並排房間**：使用者選固定層高、往下捲。
- **畫面外有人等你時，用上下緣提示條，或自動捲過去**：使用者只要電梯面板。
- **滾輪捲樓層但不能縮放、或捏合縮放**：使用者選瀏覽器原生捲軸。
- **一層太擠時桌子縮小、或排成兩排**：使用者選這層自己左右捲。
- **最新專案在最上層、依緊急程度排樓層**：使用者選先到的在 1F。
- **每層一個 Phaser 畫布**：多個 WebGL 環境，資源吃重。
- **一張很高的 Phaser 畫布**：每層的左右捲得自己模擬，與原生捲軸不一致，樓層多時可能超過畫布尺寸上限。
