# Claude 辦公室：設計

這份文件記錄**為什麼這樣做**，以及**改設計時不能破壞的規則**。其他資訊各有唯一的來源：

- 使用者看得到的行為（狀態、觸發事件、畫面元素、指令）：`README.md`
- 尺寸、顏色、時間等數值：程式碼（`web/src/floors.ts` 的 `GEO`、`web/src/styles/theme.css`、`person.ts` 的 `ENTER_MS`／`EXIT_MS`）
- hook 事件的實測結果：`docs/findings.md`

大改設計時直接修改這份文件，不另開 spec 疊加；舊版本可以從 git 歷史找回。

## 目的

同時開好幾個 Claude Code session 時，打開畫面就要一眼看出兩件事：**有哪些專案**、**哪些 session 在等我**。畫面要好看，但狀態一定要準確，排在美觀之前。

成功標準：

1. 每位員工的狀態和真實 session 一致。
2. 「等你處理」在事件發生後 1 秒內出現，而且是畫面上最醒目的東西。
3. 不管伺服器有沒有開，Claude Code 都不會變慢、也不會報錯。

## 不做

- 跨電腦或多人共用。
- 從畫面操作 session，例如批准權限、送出 prompt。唯一例外是「請他下班」，而且它只影響畫面。
- 狀態存檔：伺服器重啟後清空，等各 session 的下一個事件再補回來。
- 聲音與系統通知。
- 讀取對話內容。transcript 只讀 `ai-title` 那一行，拿來當名牌標題。

## 架構與界線

```
Claude Code ─hook─▶ src/hook/send.ts ─POST /events─▶ src/server ─reduce─▶ src/state（純函式）
                                                         │ SSE /stream（第一筆 reset＝完整狀態）
                                                         ▼
                                                  web/（DOM＋行內 SVG，Vite 建置）
```

- **hook 絕不能影響 Claude Code**：一律以結束碼 0 結束、不寫 stdout、送事件最多等 300ms，任何錯誤都安靜放棄。
- **伺服器只對本機開放**：只監聽 127.0.0.1，POST 要檢查 Origin。
- **`src/state` 是純函式**：`reduce(state, event) → { state, changes }`，不碰網路、檔案或時間，測試都放在這一層。
- **前端只畫畫面**：畫面改版不需要動 `src/`。如果要動，代表這次改的是資料模型，要另外說明理由。
- **`src/hook/send.ts --record=<資料夾>`**：錄製模式，用來錄真實事件存進 `test/fixtures/`。`findings.md` 還有沒驗證完的項目，所以先保留。

## 狀態規則背後的理由

完整的事件與狀態對應見 README「三種狀態」。下面這些不是直覺能想到的：

- **等你處理以 `PermissionRequest` 為準，不是 `PreToolUse`**：`PreToolUse` 在權限判斷之前就會觸發，`Notification` 又要晚約 6 秒才到（findings §2、§5）。
- **只有三種狀態，沒有「閒置」**：`idle` 在畫面上顯示成「輪到你」，意思是 Claude 做完這一輪，等你下一個指示。它會一直亮著，直到你送出 prompt，不會隨時間退回安靜狀態。紅色只給等你處理，輪到你用比較安靜的琥珀色，而且不脈動。
- **subagent 內部的事件（帶 `agent_id`）不改 `activity`**，也不清助理。主 session 已經 Stop 的話，這類事件也不會把狀態改回工作中。
- **背景助理（`run_in_background`）**：`PostToolUse` 和 `Stop` 都不算它完成，要等 `SubagentStop`。
- **事件先後以 hook 附上的 `sentAt` 判斷**：比較舊的事件不改狀態，但仍然可以用來補登記和配對助理。
- **幽靈員工**：強制結束 session 時收不到 `SessionEnd`（findings §4），所以要有「請他下班」和 12 小時逾時。被請下班的 session 如果還有事件進來，會重新登場。

## 畫面的決定

- **剖面大樓**：一個 cwd 一層樓，人坐在桌後面向觀看者。每層都是長方形，疊起來就是畫面的形狀，不會有暗角。這是取代等角辦公室的原因。
- **樓層順序固定**：先到的在 1F，新專案蓋在最上面。整層沒人才拆掉，上面的樓層往下補。加蓋時畫面不能跳動：原本貼在最底就維持貼底，否則錨定在目前看的那一層。
- **各層同寬，整頁橫向捲動**：每層各自左右捲，需要另外做「畫面外有人在等」的邊緣提示，太複雜，所以拿掉了。
- **畫面外的提示只有三處**：左側電梯面板的燈、狀態列、分頁標題。電梯面板只剩樓層按鈕的功能，名稱照舊。CSS 變數 `--elevator` 現在只用在屋頂的冷氣。
- **助理不佔座位**：只在主人名牌旁顯示「↳N」，N 是工作中的數量，詳細內容看資訊卡。電梯燈、狀態列、分頁標題都不算助理。
- **沒有電梯和走路**：人在座位上瞬移登場（直向光痕閃兩下，人從窄變寬、稍微超過再彈回，兩邊的殘影收回本體，約 0.35 秒）；退場時站起來雙指點額 0.3 秒，再閃三下、橫向壓成一條線，留下光痕後消失（共約 0.8 秒）。開頁面和重新連線時大家直接坐好，不播動畫。電梯進出原本是前端最複雜、又沒有測試的部分，所以拿掉，換成好維護。
- **生命力來自狀態動作**：工作中殘像打字（兩層半透明殘影，螢幕程式碼一行一行往上捲；三種狀態裡最安靜），等你處理站起來爆氣（半透明白色的火焰氣場，白天疊在奶油色牆上看不清楚，所以外圍加一圈冷藍光暈；只有角色自己抖動、整層樓不震動；氣場本身不用紅色，白天紅色只在名牌上，夜晚氣場周圍再映出一圈紅光），輪到你抱胸閉眼冥想（約每 6 秒睜開右眼、挑起右眉瞄觀看者約 0.5 秒；減少動態時停在閉眼）。每個人的動作用 sessionId 算出的延遲錯開（`view.ts` 的 `motionDelay`，`person.ts` 設成 CSS 變數 `--delay`），不會像整排機器人同步。環境也會動，但都比爆氣安靜得多（慢、幅度小）：屋頂上方的三朵雲往左飄過整片天空、飄出去再從右邊進來（大的快、小的慢），窗景的雲整片往左飄（所有窗看的是同一片天，所以一起飄；雲在全景上半部，4F 以上的窗才看得到）、盆栽的葉子輕晃、邊桌的咖啡和輪到你桌上的馬克杯冒煙。家具和桌子的動作用 `motionDelay(樓層 key + 家具或座位)` 錯開。環境動畫都寫在 `theme.css`，`building.css` 不放動畫（樓層本身不能動）。減少動態時 `#building *` 一條規則全停，煙停在半透明、不消失。
- **每層樓是淺盒舞台**：看得到天花板、後牆（下段是藍綠色護牆板）、木地板和兩側斜牆，人和家具仍然正面朝向觀看者。樓層寬度不固定，所以外殼的中段用 CSS 畫，兩側寬 16 的斜牆（連同天花板和地板的斜角）是一張固定大小的 SVG（`objects.ts` 的 `ROOM_SIDE`），右邊那張用 CSS 鏡像。木地板照設計稿畫透視：靠後牆一條較深的帶子，板縫在後緣每約 42 一條、往前散開對到樓層兩端，這要知道樓層寬，所以由 `floor.ts` 依寬度畫一張 SVG（`objects.ts` 的 `floorSeams`）。桌子、招牌和家具區離樓層左右緣各留 24（`GEO.sideGap`），不貼著斜牆；樓層寬也跟著多 48。
- **畫風**：介面（名牌、招牌、狀態列、電梯面板、資訊卡）共用一組樣式變數（`theme.css` 的 `--ui-*`）：2px 墨線框、2.5px 白外圈、往右下的半透明硬投影，值取自設計稿白天畫板的名牌；招牌和狀態列在設計稿裡投影略有不同，統一成同一組。狀態列、電梯面板、資訊卡是白底墨字，不在夜晚遮罩下，日夜長得一樣。環境是圓滾滾的機械風，和人物同一套畫法：黑色線稿、圓角、鉚釘、一階硬影（右側一塊加深的實色，不用網點）；整體配色、明暗和墨線（`#1b1716`）以設計稿白天畫板為準：天空是 `#5fb6f5` 到 `#bfe6ff` 的漸層（`--sky-bg`，固定在視窗上，頂端狀態列的底也用它才接得起來），桌子、家具、屋頂有往右下 3px 的半透明硬投影（`--drop`），讓它們離開牆面；設計稿的投影是暖褐 `#5a3418`，色相太接近琥珀，所以改用墨色。桌子是冷白（奶油色的桌子和奶油色的牆混在一起，看起來是平的），配胖胖的映像管螢幕（設計稿的深藍底：工作中是綠、藍、白輪流的亮色程式碼，空桌是一道淡藍弧；只有輪到你的螢幕是琥珀色，那是狀態信號）（畫面大、邊框窄）、每張桌子後面一把藍色椅子（不用藍綠，免得和護牆板混在一起；空桌也有，畫在人後面，椅背從人的兩側露出來）、鉚釘圓窗、圓頂水塔、圓頭立燈。雲照設計稿畫成平底、上緣三個圓包的蓬鬆輪廓加墨線（`objects.ts` 的 `CLOUD_D`），屋頂上方的雲和窗景的雲共用；線寬不跟著縮放，窗裡的小雲也看得到線。人物是鳥山明前期風的 Q 版，造型照「Claude 辦公室美術設計稿」artifact（https://claude.ai/artifact/P3nBrZxz9wgvDNEXzKgwci，白天、夜晚、雙指點額三張畫板）的定稿：大頭（寬橢圓臉，瀏海壓到眉毛、五官在臉的下半部）、黑色線稿（外輪廓 `ol` 比內線粗）、一階硬影（同色加深的實色，不用網點）、中明度飽和色的衣服、自然色的頭髮、大塊稜角髮束、只露前臂、人物本身不畫椅子（椅子是桌子那一層的物件）；眼型（角度眼加粗斜眉、大圓眼加睫毛）、髮型、髮色、衣服都由 sessionId 雜湊決定。不放原作的角色、招牌髮型、標誌或名字。
- **設計稿管整體的畫風配色，不管個別物件的顏色**：色調、明暗層次、線條和外框、夜晚的壓暗方式以設計稿為準，改了要和設計稿並排比較；爆氣氣場的白色、招牌的專案色、藍色椅子、多扇小窗看街景、狀態色是這裡自己的選擇，不跟設計稿。設計稿 artifact 是由型別建立的，`read_artifact` 讀不到：用 `list_files` 列檔，`read_file` 讀 `project/Main.dc.html`（白天）和 `project/Night.dc.html`（夜晚），去掉 `<script src="./support.js"></script>` 存成本機 html，再用 headless Edge 截圖（`--force-device-scale-factor=2 --window-size=688,600`），截完把 html、截圖和 profile 刪掉。
- **日夜依本機時間**：6:00–18:00 是白天，可以用 `?time=day|night` 固定。不看系統深色模式，切換也沒有過渡動畫。
- **夜晚是同一套顏色加遮罩**：環境顏色只有一套（`theme.css` 的 `:root`），日夜只切換天空（`--sky-bg`，夜晚是設計稿的 `#0a0f33` 到 `#2e2f6e`）和 `--day`／`--night`（雲、星星、燈罩亮起這些只在白天或夜晚出現的東西）。夜晚每層樓蓋一層 `--night-shade`（`#16224a`）的 `multiply` 遮罩、不透明度 .62，照設計稿的夜晚畫板，屋頂女兒牆和地面也蓋；水塔和冷氣不蓋，同設計稿。遮罩上用 `screen` 疊光暈（`.glow`）：桌燈和螢幕（輪到你的螢幕發琥珀光）、窗外夜空（全景在夜晚蓋一片暗夜空，壓暗後幾乎是黑的，光暈再把設計稿的夜空漸層疊回來）、立燈、販賣機，以及爆氣氣場周圍的紅光（掛在人物上，瞬移時跟氣場一起藏）。名牌、招牌、大廳紙條疊在光暈上面，夜晚和白天一樣清楚。疊放靠 z-index：遮罩 1、光暈 2、名牌和招牌 3，它們都在根的疊層裡，所以樓層、桌子、人物這幾層祖先都不能建立自己的疊層（不能加 `transform`、`filter`、`opacity`、`z-index`），不然遮罩或光暈會被關在裡面。設計稿把螢幕外殼、窗框、燈罩整個重畫在遮罩上；這裡只疊光暈，它們本身仍被壓暗，比設計稿暗一些。

## 做到了也算失敗

- 有人在等你，但不管捲到哪裡都看不出來。
- 換了畫風或動畫之後，等你處理或輪到你反而變得不醒目。
- 畫面上出現大片空白或暗角：大樓比視窗矮時，上方要是天空。
- 夜晚的文字、名牌、狀態對比太低。
- 狀態以外的東西看起來是紅色或琥珀色，掃一眼就誤以為有人在等你。
- 氣場、豎起的頭髮或手勢蓋住招牌、隔壁的人或名牌文字。稍微遮擋可以接受，在瀏覽器裡看，不寫幾何測試。

## 前端寫法規則

- **會畫錯的計算都寫成不碰 DOM 的純函式**（`floors.ts`、`view.ts`、`figure.ts`、`objects.ts`、`theme.ts`），在 vitest 的 node 環境測試。DOM 模組（`building.ts`、`floor.ts`、`person.ts`、`card.ts`、`elevator.ts`）沒有自動測試，靠 `npm run simulate` 在瀏覽器裡看。
- **前端只測邏輯和規則，不測長相**：樓層排序、名牌、日夜這類算錯了看不出來的邏輯，以及顏色、狀態色、CSS 和 SVG class 對得上這類規則，才寫測試。部件位置、外框、尺寸、畫法細節不寫測試，那只是把目前的長相釘死，改畫風時還得跟著改；這些在瀏覽器裡看白天和夜晚。
- **SVG 顏色只能寫在 `style` 或 class**，不能寫成 `fill="…"`／`stroke="…"` 屬性，因為呈現屬性不接受 `var()`，日夜切換會失效。測試會檢查這件事。
- **紅色和琥珀色只給狀態用**：環境、招牌專案色、髮色、衣服色都不能用，掃一眼才不會誤判誰在等你。狀態色只能寫在 `theme.css` 的狀態變數（`--waiting`、`--turn`、`--screen-waiting`、`--screen-turn`），大樓外殼的 CSS 只有名牌和輪到你的螢幕光（夜晚 `.desk[data-st="idle"] .glow`）能引用；人物的 CSS 只有夜晚爆氣的紅光引用 `--waiting`。光暈的顏色寫成 `rgb()`，不在 hex 掃描範圍內，新增時要自己確認不落進狀態色。`test/state-colors.test.ts` 會抽出所有 hex 色，色相離這兩色 20° 內、HSV 彩度 ≥ 0.55 就算違規。
- **人物的姿勢、表情、氣場和瞬移都交給 CSS**，依 `data-act`（work／up／idle）與 `data-fx`（in／out）切換，SVG 裡每個部件是一個可以單獨切換的群組。`person.ts` 只負責設屬性和計時。退場時一律換成工作中的臉和普通頭髮、藏起其他臉和手勢（`figure.css` 的 `[data-fx="out"]` 清單）；氣場和小石子在登場、退場時都藏（`[data-fx]`）。新增狀態部件時要加進這兩條。
- **狀態不用符號表現**：只靠名牌顏色和角色演出，不畫漫符（「噠噠」、zZ、「！」框、集中線、汗滴、打勾泡泡、「到！」、「辛苦了～」）。符號多了畫面雜，人物本身反而沒表情。
- **進出動畫放在 `.figure`，不放 `.fig`**，因為 `.fig` 的 `transform` 已經用在站起來。動畫要放在 `.person` 的子元素上，減少動態的規則才停得掉。`ENTER_MS`／`EXIT_MS` 要和 figure.css 的 keyframes 時間一致，測試直接匯入這兩個常數比對。瞬移的光痕和殘影放在人物 SVG 外面的 `.warp`（`figure.ts` 的 `WARP_SVG`），人被壓成一條線時光痕才還看得到；平常透明，減少動態時就一直看不到。
- **點額的手排在頭和頭髮後面**：SVG 後畫的蓋在前面，不這樣排手指會被頭髮蓋住。手指畫得比真的大，100px 的人物也認得出是兩根。
- **會動的部件不放在共用的 symbol 裡**：Chromium 不會把 CSS 動畫帶進 `<use>` 的複本，畫面上看起來是不動的。所以會動的部件直接放進 DOM：`objects.ts` 把它們畫成和 symbol 同外框、同座標的疊圖（`overlay`），`floor.ts` 疊在物件的 svg 上。螢幕上捲動的程式碼（`DESK_CODE`）和馬克杯的煙（`DESK_STEAM`）疊在每張桌子上，依桌子的 `data-st` 顯示；盆栽的葉子和邊桌的煙在 `FURN_ANIM`；窗景的雲是另一個 symbol（`pano-clouds`），每扇窗畫三份放進一個會平移的 `<g class="drift">`（`<use>` 元素本身可以動，動不了的只是影子樹裡面）。
- **圓窗的窗景還是方的**：窗景是一個露出全景一塊的方形 svg，圓窗的圖先用牆色（`--wall`）蓋住圓外的四個角，再畫窗框。所以圓窗只能開在素面的後牆上，後牆上段改成圖樣的話，四個角會露出來。
- **殘影往左錯開**：殘影只是照時間錯開的話，幾乎整個藏在真的手後面，所以用 `translate` 往左挪（和動畫的 `transform` 疊加）。往右挪會被螢幕擋住。
- **退場用計時器，不用 `animationend`**：樓層的 DOM 被搬動時，動畫會被取消，`animationend` 就不會觸發。

## 已否決的做法

- 等角辦公室、正面 3/4 俯視的大房間、Phaser／Canvas 黏土畫法：有暗角、資源吃重，或與原生捲動不一致。
- 專案多時把樓層變矮、改成並排房間、依緊急程度或最新專案排樓層：使用者選了固定層高往下捲，先到的在 1F。
- 畫面外有人在等時自動捲過去，或加上下緣提示條：使用者只要電梯面板。
- 縮放與拖曳鏡頭：改用瀏覽器原生捲動。
- 助理坐桌子、有自己的人物：座位分配太複雜，所以改成「↳N」。
- 每層各自左右捲加邊緣提示：所以改成同寬、整頁捲動。
- 電梯進出與走路動畫：所以改成在座位上登場和退場。
- 登場「到！」、退場「辛苦了～」貼紙：漫符，改成瞬移。
- 細墨線加網點的線稿畫風、狀態靠漫符表現：看起來像慢慢描出來的線稿，符號多、人物沒表情，所以改成鳥山明前期風和角色演出。
- AI 生圖（Gemini 免費版）：要人工反覆操作，角色在不同姿勢之間很難保持一致，最後決定不用外部資源。
- 素材包：Neko Office 禁止再散布，和公開 repo 衝突；其他免費包大多只有走路和閒置，沒有坐姿和狀態動作。
- 3D 角色渲染成 sprite（KayKit＋Blender）、Phaser／three.js：需要外部工具或即時渲染。
- 程式像素畫：臉太小，表情只剩幾個像素，狀態幾乎只能靠符號表現。
- 向量柔和插畫風、賽璐璐動漫風：雛形比較後選了鳥山明風。
- 桌上警示燈、小機器人：要用角色演出取代符號，也不加道具。
- 雛形裡的第一版演出（雙手高舉揮動、托下巴轉椅子）：改成爆氣和閉眼冥想。
- 其他工作中的動作：打字連拳太吵，會比爆氣搶眼；負重修行要靠汗滴表現，汗滴算漫符；單手倒立時臉會跑到桌子下面；集氣或氣功波的能量球太搶眼，也是原作的招牌動作。
- 紅色氣場：等你處理的紅色只放在名牌，氣場改成半透明白色（白天外圍加冷藍光暈），夜晚才在周圍映出紅光。
- 桌子和椅子用橘、紅：名牌看不清楚。奶油色桌子也否決了，和奶油色的牆混在一起；藍綠色椅子和護牆板混在一起。所以是冷白桌、藍椅。
- 夜晚換一套灰暗配色：要維護兩套顏色，看起來也不像晚上，改成同一套顏色加遮罩。
